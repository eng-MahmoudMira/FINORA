# FINORA Frontend Outcomes

- [x] **Overview Dashboard** — Include a welcome section and FINORA branding; summary KPI cards; fraud-detection, customer-churn and product-recommendation overview; recent demo activity; quick navigation to Customer 360. Use mock values only where necessary, clearly treat them as demo data, do not invent real banking performance statistics, and use clean charts and restrained visualizations.
- [x] **Customer 360 selection and profile** — Let the analyst select any of the 20 synthetic demo customers and display relevant profile information. Keep customer selection functional and preserve customer context when navigating from dashboard activity.
- [x] **Customer 360 guided decision flow** — Run in this exact order: select customer; display fraud probability, risk indicator, threshold and screening result; only when not flagged display churn probability, Low/Medium/High category (Low <30%, Medium 30–60%, High >60%) and customer risk summary; then show the top three eligible products after excluding owned products. Label offers “Retention Offers” for High churn risk and “Recommended Offers” otherwise. Finish with a unified summary containing profile, fraud result, churn risk, recommendations and overall summary.
- [x] **Fraud workflow gate** — If a transaction is flagged, display a review alert, stop the guided workflow, do not display product recommendations, and state that a prediction is a risk signal—not proof of fraud. Keep demo ground-truth labels out of prediction inputs.
- [x] **Fraud Detection page** — Provide an interactive transaction/customer screening interface, probability, threshold, status, and confusion matrix/metrics only when actual values are available. Do not invent evaluation results.
- [x] **Customer Churn page** — Provide customer selection/profile, churn probability, Low/Medium/High risk band and relevant customer information.
- [x] **Product Recommendations page** — Provide customer selection/profile, existing product ownership, ranked recommendations and probabilities; exclude every product already owned.
- [x] **Model Insights page** — Present a professional comparison of model tasks, available evaluation metrics, feature information and explanations. Clearly label supplied artifact metadata and user-provided evaluation reports with provenance; show unavailable states where evaluation evidence is absent rather than fabricating metrics.
- [x] **Branding, navigation and responsive behavior** — Use the supplied official FINORA logo assets without distortion; use a clean, premium, light banking interface, logo blue, white, #F5F8FC background, #1E293B text, #64748B secondary text, #E2E8F0 borders and Inter or a comparable sans serif. Maintain functional consistent sidebar navigation across six pages, working active states, professional spacing and layouts for desktop, laptop, tablet and mobile. Open on Overview; do not add authentication.
- [x] **Mock/backend separation and code quality** — Keep mock data separate from UI; keep a dedicated prediction service and typed customer, fraud, churn, recommendation and Customer 360 contracts; do not hardcode predictions inside components or implement model inference in JavaScript. Keep dependencies lean, buttons functional, and code organized. The frontend must be ready for a future Python API.
- [x] **Run, tests, publishing and handoff documentation** — Ensure the frontend installs, builds and tests; document setup steps, supplied data sources, limitations, mock outputs and what is required for future Python backend integration. Configure publication only after an explicit user request and use the matching server deployment contract for this SSR application.
